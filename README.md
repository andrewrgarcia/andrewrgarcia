# Featured Systems

## ⚖️ Viceroy

**Deterministic infrastructure for coding agents.**

Most coding agents generate suggestions.

Viceroy generates directly applicable edits.

Instead of asking a model to describe how code should change, Viceroy produces deterministic edit operations that can be applied automatically, verified locally, benchmarked objectively, and reproduced without an LLM judge.

Built for production AI systems—not demos.

---

## 🌲 Yggdrasil

**Knowledge representation for software.**

Repositories are larger than context windows.

Yggdrasil transforms entire codebases into structured knowledge artifacts that language models can navigate efficiently, allowing AI systems to reason over projects that would otherwise exceed their context limits.

Think of it as compiling software into knowledge.

---

## 🧠 FUR

**Conversation infrastructure for long-running AI systems.**

Chat history isn't memory.

FUR organizes conversations into structured, queryable data that supports traceability, interaction history, retrieval, and long-term context for production AI applications.

Because conversations deserve data structures.

---

## 🧊 Moxi

**An AI-native programming language for building 3D worlds.**

Moxi is a declarative language designed so that both humans **and language models** can write it naturally.

Programs are ordinary Markdown files describing geometry, materials, relationships, and behavior using syntax that remains readable while compiling into complete interactive voxel worlds.

The Rust compiler transforms Moxi source code into optimized voxel scenes, meshes, and exportable assets.

The Moxi Sandbox provides a full browser IDE with live compilation, rendering, editing, sharing, and export.

Rather than asking an AI to generate geometry directly, you ask it to write a Moxi program.

The compiler builds the world.

---

## 🎴 Deckmaster

**Presentations as code.**

Deckmaster replaces slide editors with a declarative language for building presentations.

Slides become source code.

Which means version control, reusable components, automation, scripting, AI generation, and reproducibility come naturally instead of being afterthoughts.

# Engineering Philosophy

Good software survives contact with reality.

That means software that is

- observable
- reproducible
- composable
- maintainable
- pleasant to build upon

I prefer systems that quietly keep working years later over software that briefly trends on social media.
